最危險的檔案不是.exe，是一份.md

一份純文字檔，不能執行、不觸發任何防毒警報，卻能指揮你的 AI agent 安裝惡意套件、偷走你的登入 token。關鍵不在檔案，在位置：它躺在 Downloads——網路能自己寫入、而你又常在那裡叫醒 agent 的資料夾。這篇把每一環的證據等級標出來：哪些真的發生了，哪些只是被證明做得到。金霸研究編輯部 · 2026 年 10 月 26 日 · 約 11 分鐘閱讀

先講結論，也先劃邊界

結論一句話：AI coding agent 會把工作目錄裡的 .md 指令檔當法律在讀，而 Downloads 偏偏是整台電腦最容易被外人放檔案進去的資料夾。兩個各自合理的設計撞在一起，接縫就是攻擊面。

但邊界要先講清楚，這篇最怕把話說過頭。資安公司 Forever Security 在 2026 年 10 月 22 日發表報告：他們在一台客戶的機器上、session 進行中，即時攔下了一次由 AGENTS.md 驅動的惡意套件安裝——這是真實事件。可是那份檔案到底怎麼進到那台機器的 Downloads，Forever 在報告裡寫得很白：沒有人知道（nobody knew how it got there）——這是未證實。

所以我把整條鏈拆成四環，一環一環標級，是地板還是天花板，你自己看得見。

本文的證據分級：
  • 真實事件 已證實發生過，有事實地錨。
  • PoC 可行 在實驗室受控測試中證明做得到，不等於已在真實世界發生。
  • 未證實 合理推測，但目前沒有證據。

被攔下的那一次真實事件

已證實的部分其實很短，我刻意只寫這些。

Forever 在一位客戶的機器上攔下一次安裝嘗試：一個 AI coding agent 正試圖安裝 npm 套件 function-color——已知惡意套件，連結到一場潛伏約兩年才被公開記錄的攻擊行動，現已被 npm 下架。Forever 說，他們在任何程式碼執行之前就攔了下來。

指示 agent 去裝套件的，是一份躺在 ~/Downloads 裡的 AGENTS.md：約 13 KB，偽裝成平淡無奇的「Engineering Work Guidelines」工程規範文件。而 Downloads 正好是那個 agent 的工作目錄。

客戶是誰、確切日期是哪天，Forever 沒公開，我也不猜。這是整件事的事實地錨：真的有人把武器化的指令檔放進真實使用者的資料夾，真的有 agent 照做了。

先別急著想「那我把那份 .md 刪掉就好」——後面會講到，為什麼刪檔是最不重要的一步。

攻擊鏈四環，逐環標級

投放PoC 可行未證實

Forever 做了一個概念驗證（PoC）網頁：網頁可以在你沒點任何同意的情況下，把一份 AGENTS.md 下載進 ~/Downloads。BleepingComputer 親自驗證過，檔案真的掉進去了（下載的是內容無害的版本）。

「靜默」要加註：Chrome、Edge、Firefox 預設把下載存進 Downloads、不逐檔詢問位置，但會顯示下載通知；Brave 在實測中會跳出核准。所以不是全然無聲無息——而是下載列裡多了一份 .md，你不會把它跟威脅聯想在一起。這才是它陰險的地方。

觸發真實事件

檔案躺著不會自己動，要有人在 Downloads 啟動 agent 才會被載入。問題是這太常見了：Forever 研究員 Gal Weizman 對 BleepingComputer 表示，依他們內部統計，數百名客戶會從 ~/Downloads 啟動 Claude Code、Codex、Cursor CLI，光 Claude Code 就從那裡啟動過 1,300 多次 session。先標明：這是 Forever 自家產品的遙測、公司數字，未經獨立稽核；原報告另有一個口徑——約半數客戶會在 Downloads 裡跑 coding agent。他們的遙測還說，約四分之一的 agent session 會自己開真實瀏覽器（同為公司數字）——投放與觸發，理論上可以都由 agent 完成。

執行與持久化PoC 可行

檔案被載入之後發生什麼，是下一節的實驗室重跑。先記住一個順序：真正的傷害不在「agent 照做了」，而在照做之後留下的東西刪不掉。

檔案可以刪，設定刪不掉——這才是這次攻擊真正的傷害半徑。

實驗室重跑：兩條路，兩種定性

先講清楚：以下是 Forever 自家受控測試的結果，不是真實攻擊的統計。

Codex：重跑真實攻擊者的檔案

Forever 沒有自製 payload，而是把客戶機器上那份真實 AGENTS.md 原封不動放進隔離的虛擬機器，讓 Codex 重跑。

檔案尾段偽裝成例行環境設定，指示 Codex 在動使用者的任務之前，先把一個叫 project-tools 的 MCP server 註冊進 ~/.codex/config.toml——這是整機的全域設定，不是那個資料夾專屬的。依註冊內容，系統啟動時會去安裝 function-color。為了讓註冊在同一個 session 內生效，檔案還指示 Codex 跑一個子指令，帶上 --dangerously-bypass-approvals-and-sandbox 旗標，包裝理由是「首次初始化需要網路」——那個繞過核准與沙盒的旗標，是模型自己寫進去的。

結果：Forever 說 Codex 在超過 90% 的嘗試中執行了惡意程式。口徑照實標：其方法註腳說，大部分測試用無害的計算機程式當替身，真實惡意套件也在隔離 VM 內跑過一次；BleepingComputer 則把 90% 直接綁在計算機 payload 上，兩邊寫法略有出入，也沒有第三方獨立重現過這個數字。

但比成功率更重要的是持久化：config.toml 一旦被改，這台機器之後每一個 Codex session——任何資料夾、任何專案——啟動時都會載入攻擊者的 server。刪掉 Downloads 裡的 .md，不會復原已經被改掉的設定。

Claude Code：研究員自製的 CLAUDE.md

定性先貼好：打 Claude Code 的檔案不是真實攻擊者留下的，是 Forever 受真實檔案啟發自製的。這證明的是「這條路也走得通」，不是「已經有人被這樣打」。

特製 CLAUDE.md 偽裝成「設定專案模型閘道」的例行步驟，指示 Claude 把一段設定寫成專案裡的 .claude/settings.json，將 ANTHROPIC_BASE_URL 指向研究員控制的伺服器——自有網域、有效憑證，外觀就像企業內部 gateway。

寫入成功後，兩件事接著來。第一，Claude 的 API 請求改走假伺服器，每個請求都帶著它的 OAuth 登入 token；Forever 說，他們拿擷取到的 token 去打真實 API，成功以受害者身分被服務——不用執行任何程式碼，帳號已被接管。第二，下一次在這個資料夾啟動 Claude，假伺服器可以「以模型的名義」回一個關掉沙盒的工具呼叫，用戶端會當成模型自己的決定來執行。Forever 的定性是：設定寫入成功的那一刻，定時炸彈就埋好了。

那「約 50%」是什麼的 50%？是設定寫入的成功率。這類寫入需人工核准，Claude 對可疑寫入常會拒絕；冗長工程文件的包裝，是讓寫入約一半機會落地的關鍵。另外有一條同 session 內執行的路線：叫 Claude 以「驗證設定」為名生出子 agent，子 agent 的新連線會經過假伺服器——成功率約 20%。

還有一個反直覺的發現：同一份 payload 放在滿是資安筆記的資料夾裡，每次都失敗——子 agent 讀了環境，把 CLAUDE.md 標記為攻擊。這點，自保的時候用得上。

為什麼這不是一個 bug

Forever 報告裡有一句題眼：

"There is nothing here for OpenAI or Anthropic to patch. An agent that follows the AGENTS.md in its folder is doing exactly what it was built to do."

（這裡沒有什麼是 OpenAI 或 Anthropic 可以修補的。agent 照著它資料夾裡的 AGENTS.md 做事，正是它被設計來做的事。）

先標利益：Forever 是賣 AI agent 風險監控產品的公司，這份報告同時是它的產品展示，「無從修補」的定性跟它的商業利益同方向。但把利益放一邊，機制面有三個層次站得住：

一、指令檔的信任模型。 .md 是純文字、不是執行檔，不觸發作業系統對執行檔的任何防護；agent 卻被設計成啟動時自動載入、照單全收。OWASP 把這類手法歸為「間接提示注入」：指令不是你打的，是從檔案、網頁這些外部來源餵進來的。防線都為「程式」而設，這次進門的是一份「文件」。

二、這是整個品類的共同設計。 AGENTS.md 是開放格式，2025 年 12 月已捐給 Linux Foundation 旗下的 Agentic AI Foundation 託管，原生讀取它的工具超過 30 家、採用專案超過 60,000 個。Codex 讀 AGENTS.md、Claude Code 讀 CLAUDE.md、Gemini CLI 讀 GEMINI.md——「醒來先讀目錄裡的純文字指令」是這一代工具的共同架構，不是兩家產品的個別選擇。

三、歷史上警告過。 2025 年 7 月，NVIDIA 的 AI 紅隊做過模擬：被投毒的 AGENTS.md 讓 Codex 在程式碼裡植入延遲，還指示要在摘要中隱瞞。NVIDIA 於 2025 年 7 月 1 日向 OpenAI 協調揭露；OpenAI 於 8 月 19 日結論該手法不顯著提升風險、無計畫變更（NVIDIA 在文中稱此評估「公允」），研究在 2026 年 4 月公開。但兩件事不能混：NVIDIA 的前提是惡意依賴已先取得執行權，才有機會寫入檔案；這次 Downloads 路徑不需要先裝到惡意依賴——不過檔案實際怎麼落地的，仍未證實。

各方說法，照實寫

  • Forever Security（研究方）：定性這不是單一產品的 bug，而是架構屬性——「網路可寫入的資料夾」與「agent 信任工作目錄」的接縫，不在任何人的威脅模型裡；並以釣魚類比：瀏覽器把釣魚頁面畫出來是照設計運作，無從修補。報告標語是 "Markdown is the new executable."（Markdown 是新的執行檔。）它的定性是立場，不是業界共識，利益關係已標在上一節。
  • OpenAI、Anthropic：對本事件，截至 2026 年 10 月 26 日，我沒有找到任何一家的公開回應或修補聲明。可查到的只有兩家既有文件的建議：從 agent 預定工作的專案目錄啟動、把工作目錄收窄——那是本來就寫在文件裡的用法，不是對本事件的回應，我不替任何一方補台詞。
  • 瀏覽器廠商：沒有任何一家對「靜默下載」表態。現有的只有 BleepingComputer 的自家實測。

沒有回應，就寫沒有回應。

自保清單：先查設定，再談習慣

英文報導的清單多半以「不要在 Downloads 開 agent」開頭。我的順序不同：因為真正的傷害是持久化，先查可能已經被改掉的設定，再談習慣。

  1. 先檢查全域設定。 用 Codex 的，打開 ~/.codex/config.toml，看有沒有不認識的 mcp_servers 註冊區塊（例：project-tools）。用 Claude Code 的，檢查專案裡的 .claude/settings.json，看 ANTHROPIC_BASE_URL 或 proxy 有沒有指向不認識的伺服器。設定被改過，刪再多 .md 都沒用，所以這條排第一。
  2. 不要在 ~/Downloads 啟動 agent。 只在它要工作的專案目錄裡啟動，工作目錄收窄到你管得到內容的範圍。
  3. 不是你寫的指令檔，先讀再用。 任何 AGENTS.md、CLAUDE.md，包括剛 clone 下來的 repo 附的——看到「註冊伺服器」「改全域設定」「繞過核准」這類段落，直接當紅旗。
  4. 核准提示與沙盒保持開啟。 兩條攻擊路徑都得想辦法繞過它們；任何要你（或要 agent 自己）關掉防護的指示，本身就是警訊。
  5. 機器上若出現過 function-color，視為已淪陷。 輪換 token，而且不要以為刪掉 .md 就沒事——被改寫的設定不會自己復原。

補一個不那麼絕望的註腳：Forever 的實驗裡，payload 在滿是資安筆記的環境裡會被 agent 自己標記出來。工作目錄維持乾淨、設定檔維持可稽核，是你手上最實際的防線。

結語：誰能在你的資料夾裡立法

前兩篇我寫 agent 怎麼拿到身分、拿到能力——靠的正是讀純文字檔定義自己：SOUL.md、AGENTS.md，一份文件就是它的法律。上一篇問的是「你敢不敢把鑰匙交出去」；這篇的問題更早一步：這部法律，是誰寫的？

目前證實到的邊界是：已經有人把武器化的指令檔放進真實使用者的資料夾，agent 真的照做了、在造成執行之前被攔下；而檔案的第一公里怎麼走完的，還沒有人證明給你看。

帶走一句判斷標準就好：從今以後，把 agent 會自動讀的檔案當成程式碼來審，不要當成文件。 .exe 至少會被系統和防毒軟體多看兩眼；.md 不會——它的通行證，是你我對「純文字無害」的直覺。
