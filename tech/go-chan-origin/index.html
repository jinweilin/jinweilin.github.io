我為什麼做 Go 醬？

把旅行規劃從一個人的腦袋搬出來，讓同行的人都能參與、確認，並在需要時一起修改。金霸 · 2026 年 10 月 5 日 · 約 8 分鐘閱讀

Go 醬的起點不是「AI 還能做什麼」，而是我一次又一次碰到的同一件事：每次旅行，我都要整合大家的想法、安排順序和交通方式，再把行程整理好交給大家確認。規劃看起來像一張表，實際上卻是一堆要同時放在腦袋裡的選擇。

我想解決的不是「找不到景點」，而是每次都由同一個人承擔整合與協調的腦力工作。

旅行規劃，為什麼常常變成一個人的工作？

一群人出遊時，想看的、想吃的、能走的節奏不一定相同。有人先丟一個景點，有人想到交通，有人晚一點才回覆。最後總要有一個人把零散的意見兜起來，判斷先去哪裡、怎麼移動、一天塞多少事情，再把版本送出去問大家。

這份工作不只是搜尋。它要記住每個人的偏好，理解景點之間的距離，留意時間與交通限制，還要把「大家想要的」變成一份大家看得懂、能回饋的草稿。規劃者可以做得很好，卻也容易因此成為唯一記得全貌、唯一負責收尾的人。

我想要一個助理，先把大家的想法接住

我希望同行的人能把自己的需求交給一個助理，讓它先整理內容、排出可討論的順序和交通方式，再交給大家一起確認。行程要能繼續改，也要留下大家找得到的紀錄。這樣，規劃不是一個人做完、其他人點頭；每個人都能參與，決定也能隨旅程需要調整。

這就是我做 Go 醬的原因：把反覆、繁瑣、需要記住很多事情的那一段工作交給助理處理，讓人把注意力留給真正需要一起決定的部分。不是讓助理替旅伴投票，而是讓意見更容易被整理、看見和討論。

Skill 教它怎麼規劃，Tools 讓它能接觸外部資訊

我把 Go 醬拆成兩個容易理解的部分。Skill 像一份可重複使用的工作手冊，告訴它要先問哪些必要資訊、如何檢查行程是否排得太滿、如何整理草稿，以及什麼時候該停下來請人確認。它讓助理知道這份工作的順序與規矩。

Tools 則是助理能使用的能力。以旅遊規劃為例，查公開網站可以核對景點資訊，地圖連結可以讓人自己檢查位置，行程紀錄工具則能保存已確認的規劃，讓後續調整接著同一份內容進行。工具能擴大它取得資訊和完成工作的範圍，但不會自動讓資料正確，也不會替一群人決定誰的偏好優先。

用一句話說：Skill 安排工作怎麼走，Tools 提供它能走到哪裡。這是用 Go 醬做例子的簡化說法；不同平台對 Skill、工具與 Agent 的定義和實作方式可能不同。官方文件也把 Skill 描述為可重用的指示與工作流程，並將工具列為 Agent 可直接使用的能力。[OpenAI：Skills、OpenAI：Agent definitions]

一趟行程從需求走到共同確認

1. 先把需求說清楚

目的地、日期、天數、人數和偏好，是規劃的起點；缺少重要資訊時先補問，不急著拼出一張看似完整的表。

2. 把可行性放進規劃

季節、交通距離和每天的活動量會影響行程。安排順不順，不能只看景點名稱是否排得漂亮。

3. 做出能討論的草稿

助理整理景點順序、移動方式與提醒，附上可供旅伴自行核對的資訊，讓大家有共同的討論版本。

4. 由人確認，再持續調整

草稿先交給旅客確認；確定後再保存行程。需要改動時，接著更新原本的行程紀錄，減少版本散落和舊連結失效。

這些步驟不是要把人從規劃中移除，而是把整理工作與共同決定分開。助理先做可重複、可檢查的整理；同行的人再決定取捨，確認這趟旅程適不適合自己。

工具查得到，不代表旅程已經替你決定好了

網頁資訊可能更新，營業時間和交通也可能變動；一份合理的路線，仍可能不符合同行者的體力或興趣。助理提出的內容應該是可核對的草稿，不是保證，也不該假裝掌握每個人的真正優先順序。

我仍然要負責的部分：核對重要資訊、確認大家的取捨，並在實際出發前再次確認會變動的安排。助理分擔整理，不會接手旅伴之間的溝通與最後決定。

Go 醬的故事，從我的痛點開始

我做 Go 醬，是因為我想解決自己反覆承擔的規劃負擔。對我來說，一個有用的旅行助理，不是一次吐出最多景點，而是讓需求容易提出、安排容易理解、修改有地方接續，最後讓同行的人一起確認。

它目前能做到多少，還要看每一次真實行程。之後我也會用實際旅程檢查：哪些安排真的省下整理時間、哪些地方仍要人來判斷、哪些資訊需要更早確認。這些才是 Go 醬能不能幫上忙的答案。

我不是想讓 AI 替我們旅行；我想讓它分擔規劃，好讓我們把心思留給一起出發的人。
